# EATRi8 v2 — M2 Scanning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add AI scanning to the tracker: one Scan button that handles a barcode, a nutrition label, the front of a pack, or a meal photo; returns a graded, explained, personalised result; and can be logged to a meal or saved as a custom food — metered by a monthly credit allowance with refunds on failure.

**Architecture:** Pure engine pieces in `lib/engine/**` (extraction schema, validation, merge, confidence, result builder, orchestration with injected dependencies) reuse `lib/nutrition/**`. One model adapter (`lib/engine/model.ts`, Vercel AI SDK + `@ai-sdk/google`). Credits are a Postgres ledger (`lib/credits/**`). `lib/scans/service.ts` wires engine + credits + DB; `POST /api/v1/scans` decides barcodes synchronously, charges last, and finishes AI work in `after()`. The client polls scan status.

**Plan review:** amended 2026-10-07 after an independent review (4 blockers, 16 should-fix) — amendments are written at the top of each affected task and override that task's original text.

**Tech Stack:** existing M1 stack + `ai`, `@ai-sdk/google`, `zxing-wasm` (barcode fallback), browser `BarcodeDetector` where available.

**Spec:** `docs/superpowers/specs/2026-10-06-eatri8-v2-design.md` (rev 4) — §4 credits, §7 engine, §8 API, §9 security. M1 plan (for conventions): `docs/superpowers/plans/2026-10-06-m1-tracker.md`.

## Global Constraints

- Branch `v2`; commit per task; **never push**.
- All M1 global constraints still apply (strict TS, no `any`, `lib/nutrition/**` and `lib/engine/**` (except `model.ts`) import nothing from `next`, `drizzle-orm`, `lib/db` or network modules; user-owned rows scoped by session `userId`, foreign ids → 404; JSON errors `{ error: { code, message } }`; tokens only, `text-subtle` for muted text; tap targets ≥ 44 px; Base UI `render` prop, not `asChild`).
- **No image storage in M2** (no R2, no thumbnails): images are used in memory for the model call and discarded. `scan.thumbnailKey` stays null.
- Credits (spec §4, rev 4): Basic allowance **20 AI scans / UTC month** (constant in `lib/credits/plans.ts`); 1 credit only when a model call is made; barcode scans are free; refunds are idempotent; lazy monthly reset via conditional UPDATE; per-user 5 scans / 60 s and 25 model-calling scans / UTC day; global `DAILY_AI_SCAN_CAP` (default 300).
- Uploads: `images[]` 0–3, each ≤ 1.2 MB, JPEG/WebP/PNG verified by magic bytes; whole body ≤ 4 MB; barcode must pass EAN-8/EAN-13/UPC-A check digit.
- Engine time budget: one 50 s deadline per scan, each model call `min(25 s, remaining)`, at most 1 retry (only 429/5xx/network/timeout, only if ≥ 15 s remain); route `maxDuration = 60`; stuck sweep at 3 min.
- Terminal scan writes are conditional (`WHERE status IN ('queued','processing')`); refunds only when that update hit a row.
- Label text is untrusted: schema-constrained output, string caps (name ≤ 120 chars, ≤ 80 ingredients × ≤ 80 chars, ≤ 20 meal items), numeric ranges (macros 0–100 g/100 g, energy ≤ 900 kcal/100 g).
- Models: `MODEL_FAST` default `gemini-3.5-flash-lite`, `MODEL_STRONG` default `gemini-3.5-flash` (verified against `@ai-sdk/google` 4.x known ids 2026-10-07; `scan:try` checks them against the live models API). Use the AI SDK's current structured-output API: `generateText({ model, output: Output.object({ schema }), messages, abortSignal })` → `result.output`, `result.usage` — verify against the installed `ai` package and adapt if the API differs.
- Env: `GOOGLE_GENERATIVE_AI_API_KEY` is **optional at boot** (the app must build and run without it); the scan route returns 503 `SERVICE_BUSY` with "Scanning isn't set up yet." when it's missing.

## Review Focus

1. **Double-tap Analyse** — a retried/duplicated POST with the same Idempotency-Key never charges twice and returns the same scan; each scan is charged at most once. → Task 2 concurrency test + Task 8 integration test.
2. **A slow model call that finishes after the stuck sweep** — the user must end with exactly one refund and a `failed` scan, never `done` + refunded. → Task 8 test with a fake slow engine.
3. **Barcode not in our DB or OFF, no photos** — free, clear "Barcode not found — take a photo of the label" result, no charge. → Task 8 test.
4. **A blurry/unreadable or non-food photo** — refunded, with a retake message, and the user's balance is unchanged afterwards. → Task 7 + Task 8 tests.
5. **Month rollover with leftover credits and concurrent requests** — exactly one expire + one grant per period, balance = allowance. → Task 2 test.

```ts
// ensureCurrentPeriod
const period = currentPeriod(now);
return db.transaction(async (tx) => {
  const rows = await tx.execute(sql`
    UPDATE profile p SET credits = ${allowance}, allowance_period = ${period}, updated_at = now()
    FROM (SELECT credits AS old, allowance_period AS prev, plan FROM profile WHERE user_id = ${userId} FOR UPDATE) o
    WHERE p.user_id = ${userId} AND p.allowance_period IS DISTINCT FROM ${period}
    RETURNING o.old AS old, o.prev AS prev`);
  // allowance comes from the plan: read the plan first (SELECT plan FROM profile WHERE user_id = $1) inside the tx.
  if (rows.rows.length === 1) {
    const { old, prev } = rows.rows[0] as { old: number; prev: string | null };
    if (prev && old > 0) await tx.insert(creditTxn).values({ userId, amount: -old, type: "expire", idempotencyKey: `expire:${userId}:${prev}`, balanceAfter: 0 }).onConflictDoNothing();
    await tx.insert(creditTxn).values({ userId, amount: allowance, type: "grant", idempotencyKey: `grant:${userId}:${period}`, balanceAfter: allowance }).onConflictDoNothing();
  }
  const [p] = await tx.select({ credits: profile.credits }).from(profile).where(eq(profile.userId, userId));
  return { credits: p!.credits, period };
});
```
`debitForScan(tx, userId, scanId)`: insert debit txn with key `scan:{scanId}` `ON CONFLICT DO NOTHING RETURNING id` → none ⇒ return current balance (already charged); else `UPDATE profile SET credits = credits - 1 WHERE user_id = $1 AND credits >= 1 RETURNING credits` → none ⇒ `throw new NoCreditsError()` (the caller's transaction rolls back the txn row); update the txn's `balanceAfter`; `UPDATE scan SET charged = true WHERE id = $scanId`.
`refundScan`: one transaction: insert refund txn key `refund:{scanId}` `ON CONFLICT DO NOTHING RETURNING id`; only if inserted → `UPDATE profile SET credits = credits + 1 … RETURNING credits` and set `balanceAfter`. Return whether inserted.
